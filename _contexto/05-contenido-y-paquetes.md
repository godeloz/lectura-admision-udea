## Formato de un paquete

Un paquete es un archivo `.json` que se carga en la app desde Tutor → Contenido. Puede traer lecturas con preguntas, insignias, ajustes de configuración y una novedad, juntos o por separado.

```json
{
  "paquete": "paquete-002",
  "novedad": { "version": "contenido-002", "titulo": "Lecturas nuevas", "cuerpo": "Llegaron 5 lecturas con 30 preguntas." },
  "textos": [
    {
      "codigo": "P002-T01",
      "titulo": "Título de la lectura",
      "tipologia": "argumentativo",
      "fuente": "Texto original para práctica.",
      "contenido": "Primer párrafo.\n\nSegundo párrafo.\n\n### Subtítulo\n\n- elemento de lista\n- otro elemento",
      "preguntas": [
        {
          "codigo": "P002-T01-01",
          "categoria": "inferencial",
          "dificultad": 2,
          "enunciado": "Del texto se puede concluir que:",
          "opciones": ["Opción A", "Opción B", "Opción C", "Opción D"],
          "correcta": 1,
          "explicacion": "Por qué la B es correcta y en qué falla el distractor más tentador."
        }
      ]
    }
  ],
  "insignias": [
    { "codigo": "racha-14", "nombre": "Dos semanas", "descripcion": "Catorce días seguidos practicando.",
      "icono": "🎼", "color": "rosa", "orden": 13, "regla": { "tipo": "racha", "valor": 14 } }
  ],
  "config": { "alertas": { "dias_inactividad": 2, "caida_puntos": 15, "minimo_respuestas": 5 } }
}
```

### Campos

| Campo | Valores |
|---|---|
| `paquete` | Nombre del paquete. Obligatorio. |
| `textos[].codigo` | Único. Patrón: `P` + número de paquete + `-T` + número de lectura. |
| `textos[].tipologia` | `ensayo`, `divulgacion`, `literario`, `discontinuo`, `intertextual`, `argumentativo`, `periodistico`, `otro` |
| `textos[].contenido` | Texto con `\n\n` entre párrafos. Admite `### subtítulo`, `- lista`, `**negrita**` y `*cursiva*`. Un `\n` simple se conserva como salto de línea (sirve para versos). No admite imágenes ni tablas. |
| `textos[].fuente` | Línea de crédito al pie de la lectura. |
| `preguntas[].codigo` | Único. El de la lectura más `-01`, `-02`… |
| `preguntas[].categoria` | `literal`, `inferencial`, `critico`, `cohesion` (sin tildes) |
| `preguntas[].dificultad` | 1, 2 o 3. Si falta, queda en 2. |
| `preguntas[].opciones` | Exactamente 4. |
| `preguntas[].correcta` | 0 = A, 1 = B, 2 = C, 3 = D |
| `preguntas[].explicacion` | Se muestra tras responder y en el diagnóstico. |
| `"activo": false` | En una lectura o pregunta: la retira sin borrarla ni perder su historial. |
| `insignias[].color` | `rosa`, `cian`, `amarillo`, `menta`, `violeta` |
| `insignias[].regla` | Ver los tipos en `04-reglas-y-formulas.md`. |
| `config` | Claves: `distribucion`, `categorias`, `retos`, `simulacros`, `xp`, `rangos`, `referencias`, `alertas`, `avatares`. **Cada clave se reemplaza completa:** hay que copiar el valor actual y cambiar solo lo necesario. |

### Lo que hay que saber antes de cargar

- **Cargar un código que ya existe lo sobrescribe.** Sirve para corregir una errata. El validador no avisa si un código «nuevo» coincide con uno de otro paquete, así que hay que revisar la numeración: el siguiente paquete es `paquete-006` y sus códigos empiezan por `P006-`.
- **Recargar un paquete repite su novedad.** Para una corrección, quitar el campo `novedad`.
- **El validador de la app revisa:** que sea JSON válido, que tenga `paquete`, que cada lectura tenga código, título y contenido, que la tipología exista, que cada pregunta tenga código no repetido dentro del paquete, categoría válida, cuatro opciones, `correcta` entre 0 y 3, dificultad entre 1 y 3 y enunciado; y que cada insignia tenga código, nombre y tipo de regla.
- **El validador no revisa:** que haya explicación, que la respuesta marcada sea de verdad la correcta, ni que las posiciones A a D estén repartidas. Eso se revisa leyendo.
- Tras cargar, la estudiante recibe las preguntas nuevas en su siguiente reto. No hay que subir versión ni tocar GitHub.

### Dónde se guardan

Cada paquete se guarda como `content/paquete-00N.json` en esta carpeta, aunque la app no lea esos archivos en producción (lee la base de datos). Son el respaldo del banco: si un día hubiera que montar otra base de datos, se cargan de nuevo en orden.

Lo mismo con los ajustes: cuando se cambie la configuración con un paquete, conviene guardarlo (por ejemplo `content/ajustes-2026-10.json`) y anotarlo en la bitácora, porque `content/base.json` solo refleja los valores de fábrica.

## Criterios para escribir lecturas

- **Si se usa un texto de dominio público** (como el poema de `paquete-004`), cotejarlo con una edición confiable antes de cargar: las versiones que circulan en internet difieren en puntuación y mayúsculas.
- **Originales o de dominio público.** Las lecturas de `paquete-001` se escribieron para la app («Texto original para práctica»). No se copian textos de cuadernillos ni de autores con derechos vigentes: la app está publicada en internet. Si se usa un fragmento real, que sea de dominio público y con su fuente.
- **Variedad de tipologías** en cada paquete: ensayo o texto argumentativo, divulgación científica, texto literario (narrativo o poético), dos textos en diálogo y un texto discontinuo. El examen trabaja mucho con ensayo de humanidades y prosa académica densa; conviene que el banco lo refleje.
- **Extensión.** Las de `paquete-001` tienen entre 160 y 270 palabras. El examen real combina párrafos densos de unas cien palabras con lecturas de tres o cuatro párrafos largos. Vale la pena ampliar el rango: entre 120 y 450 palabras, con algunas lecturas largas que entrenen la resistencia.
- **Registro.** El examen usa vocabulario culto («conculcar», «farragosa», «sediciosas») y sintaxis compleja. Las lecturas de dificultad alta deben exigir eso mismo. Las fáciles pueden ser más llanas, sin volverse infantiles.
- **Temas.** Cultura, ciencia, arte, lenguaje, historia, vida contemporánea. Como la estudiante disfruta la música y los videojuegos, algunas lecturas sobre esos mundos ayudan a que le importe lo que lee, siempre con rigor.
- **Textos discontinuos.** Hoy solo pueden ser texto: una infografía se escribe con subtítulos y listas. Las caricaturas o gráficas reales necesitarían soporte de imágenes, que la app no tiene.
- **Datos inventados, marcados como tales.** La infografía de `paquete-001` lo dice en su fuente: «Infografía con datos ficticios, elaborada para práctica».

## Criterios para escribir preguntas

- **Seis preguntas por lectura** es la medida de `paquete-001`. Puede variar entre 4 y 8 según la lectura.
- **Distribución por paquete** cercana a 20 % literal, 35 % inferencial, 30 % crítico y 15 % cohesión. En un paquete de 30: 6, 10 u 11, 9 y 4 o 5. Mientras la matriz tenga huecos, los paquetes siguientes deben cubrirlos antes que respetar la proporción.
- **Dificultad.** Criterio de trabajo:
  - 1: la respuesta está en una frase del texto o es una reformulación directa.
  - 2: hay que integrar dos partes del texto, interpretar un término o una figura, o reconocer la función de un conector.
  - 3: hay que evaluar un argumento, comparar posturas, detectar lo que el texto no permite concluir, o descartar distractores muy plausibles.
- **Distractores como los del examen:** una extrapolación que el texto no sostiene; una afirmación razonable pero ajena a la intención del autor; una contradicción sutil; una opción que acierta en la conclusión y falla en la razón; el dato correcto de la fila equivocada.
- **Enunciados con los patrones del examen** (ver `02-examen-y-metodologia.md`): actitud análoga, sentido de unas comillas, referente de una expresión, figura retórica, sinónimo en contexto, resumen del pensamiento del autor, preguntas en negativo con «NO» o «MENOS», presuposiciones, función de un conector o de un signo de puntuación.
- **Cuatro opciones de extensión parecida.** Que la correcta no sea siempre la más larga ni la más matizada. Al escribir, la correcta tiende a salir más larga que los distractores: hay que contarlo. En `paquete-002` es la más larga en 7 de 31 preguntas, en `paquete-003` en 6 de 32, en `paquete-004` en 8 de 30 y en `paquete-005` en 5 de 27, cerca de lo esperable por azar. En los primeros borradores de `paquete-004` y `paquete-005` lo era en más de la mitad: hay que medirlo siempre.
- **Explicaciones sin letras ni posiciones.** Nada de «la opción B» o «la última opción»: las opciones se reubican al armar el paquete y la referencia quedaría mal.
- **Que una explicación no regale otra pregunta.** En un reto las preguntas de una misma lectura salen seguidas y la explicación aparece enseguida; si la explicación de una resuelve la siguiente, esa segunda pregunta no mide nada.
- **Las citas, exactas.** Todo lo que vaya entre comillas angulares en un enunciado debe estar tal cual en la lectura.
- **La correcta repartida entre A, B, C y D** en todo el paquete.
- **Explicación que enseña.** Dos o tres frases: por qué la correcta lo es, con apoyo en el texto, y en qué falla el distractor más tentador. Cuando aplique, nombrar el tipo de error («confundir correlación con causa», «leer mal a qué remite una expresión»). Modelo, de `paquete-001`: *«La nota muestra que dos cosas aparecen juntas, no que una cause la otra: quizá quienes ya leen mucho buscan más recomendaciones. Confundir correlación con causa es un error crítico frecuente.»*
- **Cada pregunta se responde con el texto**, no con cultura general.

## Cómo pedir un paquete nuevo a Claude

> Lee `_contexto/05-contenido-y-paquetes.md` y los paquetes que hay en `content/`. Genera el paquete siguiente para Entrelíneas: 5 lecturas originales (un ensayo de humanidades, un texto de divulgación científica, un texto literario, dos textos en diálogo y un texto discontinuo), de 6 a 8 preguntas cada una. Mira en «El banco hoy» qué falta y cúbrelo primero. Que haya lecturas enteras fáciles y lecturas enteras difíciles. Reparte la respuesta correcta entre A, B, C y D y cuida que no sea siempre la opción más larga. Explicaciones que digan por qué la correcta lo es y en qué falla el distractor más tentador. Guárdalo en `content/`, valídalo contra el formato, pruébalo en el demo y muéstrame la tabla de niveles y dificultades antes de que yo lo cargue.

## Antes de cargar: lista de revisión

1. Leer cada lectura completa. ¿Se sostiene como texto, sin las preguntas?
2. Responder cada pregunta sin mirar la clave. Si la respuesta propia no coincide, la pregunta es ambigua o la clave está mal.
3. Comprobar que ninguna opción incorrecta sea defendible.
4. Revisar códigos: correlativos, sin repetir, con el prefijo del paquete.
5. Contar niveles, dificultades y posiciones de la correcta.
6. Pegar el paquete en Tutor → Contenido → **Revisar paquete**. Si dice que está listo, **Cargar paquete**.
7. Mirar la tabla «Banco de preguntas» del panel para confirmar los totales.
8. Guardar el archivo en `content/` y anotarlo en `_contexto/09-bitacora.md`.

Una forma segura de probar un paquete antes de llevarlo a la app real es cargarlo primero en `demo.html`, entrando como `tutor` / `demo`, y hacer un reto como `sofia` / `demo`.

| `preguntas_b.py` | Patrones, Geometría y las situaciones |

`python3 tools/generar_logica.py` escribe `content/logica-base.json`, `logica-001.json`, `logica-002.json` y `plantilla-logica.json`, y antes de escribir:

- ejecuta la comprobación de cada pregunta que la tenga (`chk`): la cuenta hecha en Python o el acertijo resuelto por fuerza bruta. Si alguna falla, se detiene;
- revisa que la técnica exista, que no haya opciones ni códigos repetidos y que cada distractor tenga tipo de error y nota;
- reparte la respuesta correcta entre A, B, C y D, parejo dentro de cada paquete;
- imprime la tabla de niveles y dificultades, las preguntas por técnica y en cuántas la correcta es la opción más larga.

Una pregunta se escribe así:

```python
q("POR-2", "porcentajes", 2, 2,              # código corto, técnica, dificultad, paquete (1 o 2)
  "Llenar el tanque de una moto cuesta $40.000. Si el precio de la gasolina sube 20 %, ¿cuánto cuesta llenar 3/4 del tanque?",
  "$36.000",                                  # la respuesta correcta
  [("$30.000", INC, "Calculaste los 3/4 con el precio viejo. Falta aplicar el aumento del 20 %."),
   ("$48.000", INC, "Ese es el tanque completo con el precio nuevo. Falta tomar los 3/4."),
   ("$38.000", REG, "Sumaste 3/4 y 20 % como si fueran partes del mismo total. El aumento se multiplica, no se suma.")],
  "Son dos pasos que se multiplican: precio nuevo del tanque completo y, de eso, los 3/4.",   # pista
  ["Tanque completo con el aumento: 40.000 × 1,20 = 48.000.", "Tres cuartos de eso: 48.000 × 3/4 = 36.000.", "…"],  # pasos
  "Dos cambios seguidos se multiplican.",    # idea clave
  chk=lambda: 40000 * 1.2 * 0.75 == 36000)   # comprobación
```

Los códigos finales llevan el prefijo `L-`: `L-POR-2`, `L-S02-1` (pregunta 1 de la situación S02). Como todos los códigos, son para siempre. Para un paquete nuevo (`logica-003`) se sigue la numeración de cada técnica: `POR-5`, `POR-6`… y las situaciones siguen en `S05`.

### Formato de un paquete de lógica

El modelo completo es `content/plantilla-logica.json`. Campos propios, además de los de lectura:

| Campo | Valores |
|---|---|
| `preguntas[]` (en la raíz) | Problemas sueltos, sin texto compartido |
| `textos[].tipologia` | `situacion` para un contexto de lógica. Todas sus preguntas deben ser de lógica |
| `textos[].figura`, `preguntas[].figura` | SVG. Trazos con `currentColor`; la app lo pinta sobre papel claro |
| `preguntas[].categoria` | `deductivo`, `proporcional`, `abstracto`, `geometrico` |
| `preguntas[].tema` | Código de una técnica que exista o que venga en el mismo paquete |
| `preguntas[].pista` | Una o dos frases |
| `preguntas[].pasos` | Lista de textos. Admiten **negrita** |
| `preguntas[].errores` | Lista de 4, en el orden de las opciones: `null` en la correcta y `{"tipo": …, "nota": …}` en las demás |
| `preguntas[].explicacion` | En lógica es la idea clave, en una frase |
| `tecnicas[]` | `codigo`, `categoria`, `nombre`, `cuando`, `pasos`, `ejemplo`, `trampa`, `orden` |

El enunciado y el contenido de una situación admiten párrafos, listas (`- `), **negrita** y cuadros: filas que empiezan y terminan con `|`, la primera como encabezado. No hay notación matemática especial: se escribe con los signos corrientes (×, ÷, −, ², π, 3/4).

El validador de la app revisa, además de lo de lectura: que la categoría corresponda al componente del lugar donde está la pregunta, que `errores` tenga 4 posiciones con `null` en la correcta y tipos conocidos, que `pasos` sea una lista, que `figura` sea un SVG y que la técnica exista. No revisa que la respuesta sea la correcta: para eso está la comprobación del generador.

### Criterios para escribir problemas de lógica

- **Originales.** No se copian problemas de cuadernillos. Sí se siguen sus tipos: la guía de la UdeA y `simulacro-udea-b.md` son la referencia de estilo.
- **Aritmética limpia.** El examen no permite calculadora. Los resultados salen exactos y las cuentas se pueden hacer a mano en menos de dos minutos.
- **Dificultad.** 1: un solo movimiento, aplicación directa de la técnica. 2: dos movimientos o una trampa de lectura. 3: tres pasos encadenados, dos condiciones a la vez o una pregunta en negativo («la única que no se puede asegurar»).
- **Cada distractor sale de un error concreto**, y la nota lo nombra en segunda persona: qué hizo quien lo marcó y qué le faltó. Si no se puede decir de qué error sale una opción, es un mal distractor. Tipos: `enunciado`, `planteamiento`, `regla`, `incompleto`, `calculo`, `inferencia` (definidos en `02`).
- **La nota no usa letras ni posiciones**, igual que en lectura.
- **Pista que no regala.** Dice por dónde empezar o qué preguntarse. Nunca un resultado intermedio que deje el problema a una operación.
- **Pasos cortos**, uno por movimiento, con la operación escrita. El último llega a la respuesta. Cuando hay una forma de comprobar o un atajo, va como paso final.
- **Idea clave** en una frase que sirva para el siguiente problema del mismo tipo, no solo para este.
- **Una explicación no regala otra pregunta.** En una situación, los pasos de una pregunta no deben resolver la siguiente.
- **Figura solo si hace falta**, y con las medidas que el enunciado menciona. Hay que mirarla dibujada: una cota mal puesta cambia el problema.
- **Contextos** cercanos a la estudiante (música, arte, dibujo, videojuegos, la ciudad), sin que el contexto estorbe la lectura.
- **Comprobación en código** siempre que la respuesta se pueda calcular o enumerar.
